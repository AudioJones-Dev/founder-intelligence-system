# Founder Intelligence System

Founder Intelligence System is a canonical intelligence layer for founder cognition, operating judgment, organizational memory, and strategic reasoning. It is a markdown-first, schema-first repository designed to make operational intelligence explicit, reusable, and machine-readable.

This repository is not an application. It is a semantic architecture.

## Why this exists

Founder-led organizations generate high-value strategic insight, but most of it stays trapped in meetings, intuition, and fragmented notes. This system exists to:

- convert tacit reasoning into structured intelligence assets,
- preserve decision context over time,
- enable consistent interpretation across humans and AI agents,
- reduce strategic drift caused by memory loss and ambiguous language.

## Architecture philosophy

> Complexity exists in the architecture. Not in the reading experience.

The design standard is simple to read, strict to interpret, and durable over time.

### Semantic distinctions

- **Skills**: repeatable cognitive operations (how to detect, analyze, or decide).
- **Frameworks**: composed systems of skills used to solve recurring strategic problems.
- **Doctrine**: worldview and strategic interpretation rules that constrain how frameworks are applied.
- **Ontology**: shared semantic definitions and relationship types that keep terms consistent across the system.

## AI-native design principles

1. **Semantic clarity first** — explicit names, explicit intent, explicit outputs.
2. **Composable primitives** — skills can be reused inside frameworks and agent workflows.
3. **Schema-backed assets** — structures are machine-parseable for retrieval and routing.
4. **Retrieval-ready writing** — concise, sectioned markdown optimized for human + AI scanning.
5. **Long-term continuity** — preserve interpretation context, not just final decisions.

### Core directories

- `skills/` — canonical skill specifications.
- `frameworks/` — composed reasoning systems.
- `doctrine/` — strategic philosophy and epistemic constraints.
- `ontology/` — semantic entities, relationship vocabulary, and typing consistency.
- `schemas/` — JSON schemas for validation and routing compatibility.
- `agents/` — agent role definitions and execution behavior.
- `prompts/` — prompt assets aligned to skills/frameworks.
- `transcripts/` — raw source intelligence (calls, meetings, interviews).
- `extractions/` — structured outputs derived from transcripts.
- `research/` — supporting evidence, references, and investigations.
- `meta/` — system-wide maps, taxonomy, routing logic, retrieval strategy.
- `templates/` — authoring standards for new intelligence assets.

## Contribution standards

- Write for semantic precision, not stylistic flourish.
- Follow required templates and section order.
- Keep each file single-purpose and composable.
- Use shared ontology terms where possible.
- Prefer explicit relationships over implicit assumptions.

See `CONTRIBUTING.md` for contribution protocol.

## Semantic architecture model

The operating sequence is:

1. Doctrine sets interpretation boundaries.
2. Frameworks organize strategic reasoning flows.
3. Skills perform atomic cognitive operations.
4. Ontology normalizes terms and relationships.
5. Agents/prompt systems execute and route these assets.
6. Transcript extraction systems feed new intelligence back into the architecture.

## Long-term vision

This repository is designed to become the semantic operating system for founder-led decision environments: a durable intelligence substrate that supports future agent systems, operational diagnostics, and organizational memory infrastructure without losing conceptual integrity.
